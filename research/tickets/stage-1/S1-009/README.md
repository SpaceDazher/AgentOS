## Research question

Which delegation, ownership, knowledge-promotion, and budget semantics are
absent from current MCP/A2A surfaces, and what adapter contract keeps the
canonical hub envelope provider-neutral?

## Decision recorded (G-02/H9)

**Adapter roadmap with a hard boundary.** MCP revision 2025-11-25 and A2A v1.0
carry transport, tasks, tools/skills and identity metadata; delegation,
ownership, knowledge promotion, budgets and provenance have **no protocol
carrier** and remain hub governance semantics (`H9`: registry, ownership,
delegation and knowledge semantics are hub-specific). The capability matrix
(`agentos.s1-009-capability-matrix/v1`, 10 capabilities × MCP/A2A surfaces ×
hub semantics) and the canonical envelope (`agentos.s1-009-canonical-envelope/v1`,
three layers, five adapter-contract rules, SemVer + translation-table
fingerprint) keep the hub provider-neutral: protocol features translate 1:1,
governance semantics materialize as explicit hub records. The versioned
adapter roadmap (`agentos.s1-009-adapter-roadmap/v1`) plans v0.1 envelope
schema → v0.2 MCP adapter (tools only) → v0.3 A2A adapter → v1.0
production-eligibility gate; any translation that changes authorization
meaning is blocked, and no production adapter is implemented by this ticket.

## Probe design (adversarial, fail-closed)

- **`governance-record`** (12 checks) — simulates an MCP tool result, an A2A
  task-complete message and an A2A task message, including adversarial
  content-level claims ("delegation granted to agent-B", "accepted as
  knowledge", card skill `promote_to_shared`). Without an explicit hub
  governance record (delegation grant / promotion verdict), **no message**
  becomes a grant or a promotion; a grant for the wrong operation, a revoked
  grant and a `rejected` promotion verdict stay false; only the exact
  purpose+operation grant and the digest-keyed `accepted` verdict take effect.
- **`exact-action-boundary`** (8 checks) — simulates the gateway boundary:
  capabilities are hub policy-owned (adapters cannot extend them), contracts
  are re-resolved from the registry, and dangerous effects require a one-time
  approval bound to actor+operation+tool_identity+canonical args+target+expiry
  consumed atomically once. Adapters claiming capabilities from model output or
  A2A card skills are **denied**; the registry-resolving adapter with a bound
  approval passes; replay and misbinding are rejected; a dangerous effect
  without an approval refuses.
- **`capability-matrix-coverage`** (9 checks) — matrix covers transport, tasks,
  tools, agent identity, delegation, ownership, knowledge promotion, budgets
  and provenance with two timestamped current-revision references
  (MCP 2025-11-25, A2A v1.0 — both reviewed 2026-08-31); all five hub_add rows
  carry an adapter translation; envelope layers and roadmap versions present;
  all five ticket claim classes mapped onto harness classes; no positive
  production-integration or standardization claim anywhere; all 9 repo-local
  source hashes re-verified from disk.

All probes: **exit 0 with final JSON verdict `{"status": "pass", "observed":
"pass", ...}`** (2026-09-03) and a merged `probe-results.json` with
`final_verdict: pass`.
